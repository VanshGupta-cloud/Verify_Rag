# Phase 2 Plan: Milestone 2 Generation & Claim Decomposition

## Objective
Establish the LLM generation and atomic claim decomposition layer for VerifyRAG:
1. **Pluggable Generator Adapter (`src/pipeline/generator.py`)**:
   - Provider abstraction supporting Groq (`llama-3.3-70b-versatile`), OpenAI (`gpt-4o-mini`), Ollama (`llama3:8b`), and deterministic `MockGenerator` for offline testing.
   - Context-grounded RAG prompt formatting with chunk metadata injection.
   - Robust error handling, latency telemetry recording (`draft_generation_ms`), and API fallback handling.
2. **Atomic Claim Decomposition Engine (`src/pipeline/claim_splitter.py`)**:
   - Partitioning continuous draft answers into discrete, verifiable atomic factual propositions $C = \{c_1, c_2, \dots, c_n\}$.
   - Deterministic sentence boundary detection + clause splitting (conjunctions, semicolons, relative clauses).
   - Optional spaCy integration with high-precision regex/rule-based fallback.
   - Claim filtering (discarding non-factual intros/disclaimers like "Sure, here is the answer:").
   - Telemetry recording (`claim_split_ms`) and canonical `Claim` schema instantiation.
3. **Phase 2 Verification Suite (`tests/test_milestone_2.py`)**:
   - Unit tests for all generator providers (including mock and error cases).
   - Unit tests for claim decomposition across compound, complex, and list-based text.
   - End-to-end integration test: retrieved chunks -> draft generation -> claim decomposition -> schema validation.

## Execution Waves

### Wave 1: Generator Architecture & Prompt Templates
- **Task 1.1:** Create `src/pipeline/__init__.py`.
- **Task 1.2:** Implement `src/pipeline/generator.py`:
  - `BaseGenerator` abstract base class defining `generate(query: str, context_chunks: List[Chunk]) -> Tuple[str, float]`.
  - `GroqGenerator`, `OpenAIGenerator`, `OllamaGenerator`, and `MockGenerator`.
  - Factory function `get_generator(provider: Optional[str] = None) -> BaseGenerator` referencing `src.config.Settings`.
  - Grounded prompt template instructing the model to answer based on provided context chunks.

### Wave 2: Atomic Claim Decomposition Engine
- **Task 2.1:** Implement `src/pipeline/claim_splitter.py`:
  - `ClaimSplitter` class with configurable min length, punctuation normalization, and clause boundary detection.
  - Sentence segmentation (handling abbreviations e.g., 'U.S.', 'e.g.', 'Dr.', decimals).
  - Clause decomposition on coordinating conjunctions ("and", "but", "while") when both clauses contain independent propositions.
  - Heuristic filter for non-factual conversational framing ("Based on the provided context...", "Here is what I found:").
  - Returns canonical `List[Claim]` with unique sequential IDs and default `verdict=UNSUPPORTED`.

### Wave 3: Integration & Testing
- **Task 3.1:** Implement `tests/test_milestone_2.py`:
  - Test mock generator produces prompt-grounded text and records latency.
  - Test generator factory correctly resolves providers and configuration defaults.
  - Test claim splitter decomposes compound sentences into atomic propositions.
  - Test claim splitter filters noise / non-verifiable conversational pleasantries.
  - Test pipeline chaining: mock chunks -> generator -> claim splitter -> canonical `Claim` list.

## Verification Criteria
- [ ] Strict type hinting throughout `src/pipeline/generator.py` and `src/pipeline/claim_splitter.py`.
- [ ] Fully functional offline without requiring mandatory cloud API keys (using `MockGenerator` or local fallback).
- [ ] All claims instantiate valid canonical `Claim` models defined in `src/schemas.py`.
- [ ] Comprehensive test suite in `tests/test_milestone_2.py` passes 100%.
